1. ЗАГАЛЬНИЙ ОПИС ПРОЄКТУ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Проєкт — автоматизована система публікації аніме-постів у Telegram-канал.
Бот самостійно обирає аніме зі своєї бази даних, формує пост (назва, рік,
рейтинг, опис, жанри, зображення) та публікує його за розкладом або за командою
адміністратора.

Основні можливості:
  - Автоматичний постинг за налаштованим інтервалом (6–9 год за замовчуванням)
  - Ручний запуск публікації через Telegram-команди (/post_now, /post_anime)
  - Пошук аніме за назвою (точний та fuzzy-пошук через rapidfuzz)
  - Інтелектуальний вибір аніме: вагова система з урахуванням рейтингу,
    популярності, року та жанрів
  - Система cooldown: повторна публікація одного аніме блокується на 14–90 днів
  - Кешування зображень через Telegram file_id (уникнення повторних завантажень)
  - Dry run режим: симуляція публікації без реального надсилання
  - Парсинг бази аніме з Shikimori API
  - Адміністративне управління через Telegram-команди

Взаємодія компонентів (рівень):
  Telegram ← bot (команди, inline-кнопки)
       ↓
  services (бізнес-логіка: вибір, публікація, автопостинг)
       ↓
  db (SQLite через SQLAlchemy: аніме, жанри, публікації)
       ↓
  parsers / scripts (наповнення та збагачення БД з Shikimori API)

APP (app/) — конфігурація, спільний стан, утиліти:
  settings.py     — змінні середовища та runtime-налаштування
  runtime_state.py — потокобезпечний стан бота (enabled, dry_run, interval)
  priority_weights.py — алгоритм ваг та штрафів для вибору аніме
  lockfile.py     — атомарне блокування через файл (запобігання паралельним циклам)
  logging_config.py — централізоване налаштування логування

3. СТРУКТУРА ПАПОК
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

bot/
  Telegram-рівень. Обробляє команди від адміністратора, формує тексти постів,
  надсилає повідомлення через python-telegram-bot. Не містить бізнес-логіки.

services/
  Бізнес-логіка. Координує вибір аніме, публікацію та автопостинг.
  Є посередником між Telegram-шаром і базою даних.

scripts/
  Утиліти та batch-задачі. Парсинг, збагачення БД, міграції, діагностика.
  Запускаються вручну через консоль, не залежать від бота.

db/
  Визначення моделей SQLAlchemy та підключення до SQLite.
  Єдина точка доступу до бази для всіх компонентів.

app/
  Спільна конфігурація та утиліти. Налаштування середовища, глобальний стан
  бота, алгоритм ваг, блокування, логування.

parsers/
  HTTP-клієнт для Shikimori API. Відповідає за завантаження даних про аніме.
  Використовується лише скриптами (full_parse, enrich_anime).

tests/
  Автоматизовані тести (pytest). Покривають: логіку cooldown, вагову систему,
  форматування, цикл публікації, інтеграцію з in-memory SQLite.

docs/
  Документація проєкту: чеклист ручного тестування, архітектурний опис.

4. ОПИС КЛЮЧОВИХ ФАЙЛІВ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Файл: bot/telegram_bot.py
Призначення: Точка входу Telegram-бота.
Що робить: Реєструє обробники команд (/post_now, /status, /posting_on та ін.)
та inline-кнопок. Запускає фоновий цикл автопостингу. Перевіряє права
адміністратора перед кожною дією. Управляє файловим блокуванням (один екземпляр).

Файл: bot/telegram_sender.py
Призначення: Надсилання повідомлень у Telegram-канал.
Що робить: Реалізує два режими — без кешу (send_post) та з кешем file_id
(send_post_with_cache). У другому режимі зберігає Telegram file_id у БД після
першої відправки, щоб не завантажувати зображення повторно. Обробляє BadRequest
(протермінований file_id) та fallback на URL при великих файлах.

Файл: bot/formatter.py
Призначення: Формування тексту поста.
Що робить: Очищує опис від BBCode-тегів ([b], [url], [character] тощо),
обрізає текст по слову до ліміту, підставляє хештеги жанрів та формує
фінальний шаблон поста.

Файл: services/publisher.py
Призначення: Основний pipeline публікації одного аніме.
Що робить: Формує текст → надсилає в Telegram → записує PublishedAnime у БД.
Використовує одну транзакцію для запису file_id і PublishedAnime, щоб
уникнути неузгодженого стану при помилках.

Файл: services/post_cycle.py
Призначення: Один повний цикл постингу.
Що робить: Захоплює файловий lock → викликає get_random_anime → викликає
publish_anime → повертає словник зі статусом ("ok", "no_anime", "locked",
"error"). Є єдиною точкою входу для Telegram-команд і автопостингу.

Файл: services/auto_poster.py
Призначення: Фоновий asyncio-цикл автопостингу.
Що робить: Нескінченний цикл, який читає стан з RuntimeState (enabled/interval),
викликає run_post_cycle в executor-потоці та засинає на рандомний інтервал.
Запускається при старті бота.

Файл: scripts/get_random_anime.py
Призначення: Інтелектуальний вибір аніме для публікації.
Що робить: Формує два пули кандидатів (топ за популярністю + рандомна вибірка),
фільтрує за якістю (members, опис, жанри, kind), перевіряє cooldown, рахує
ефективну вагу кожного аніме з урахуванням штрафів, обирає рандомно з топ-50.

Файл: app/priority_weights.py
Призначення: Алгоритм корекції ваг для запобігання одноманітності.
Що робить: Аналізує останні N публікацій, знаходить домінуючі категорії
(статус, рік виходу, жанр) і застосовує штрафні множники до аніме з цих
категорій. Це автоматично урізноманітнює вибір без ручного налаштування.

Файл: app/runtime_state.py
Призначення: Потокобезпечний глобальний стан бота.
Що робить: Зберігає поточні налаштування (posting_enabled, dry_run, interval,
is_posting_now), які можна змінювати через Telegram-команди під час роботи бота.
Всі поля захищені threading.Lock для безпечного доступу з різних потоків.

Файл: app/lockfile.py
Призначення: Атомарне файлове блокування.
Що робить: Використовує O_EXCL при відкритті файлу, що гарантує атомарність
захоплення блокування навіть між різними процесами. Запобігає одночасному
запуску кількох екземплярів бота або паралельним циклам публікації.

Файл: db/models.py
Призначення: ORM-моделі бази даних.
Що робить: Визначає таблиці Anime, Genre та PublishedAnime через SQLAlchemy
Declarative Base. Описує зв'язки (many-to-many між Anime і Genre).

Файл: scripts/full_parse.py
Призначення: Початкове наповнення бази даних з Shikimori API.
Що робить: Посторінково завантажує список аніме, парсить деталі кожного,
зберігає в SQLite. Підтримує checkpoint для безпечного відновлення після
переривання.

Файл: scripts/enrich_anime.py
Призначення: Збагачення існуючих записів (kind, members).
Що робить: Знаходить записи з NULL-полями, запитує Shikimori API, обчислює
members як суму rates_statuses_stats, зберігає результат. Ідемпотентний,
з checkpoint і retry-логікою.

5. ОСНОВНІ ФУНКЦІЇ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Функція: run_post_cycle()
Де: services/post_cycle.py
Призначення: Єдина точка входу для запуску одного циклу публікації.
Як працює: Захоплює файловий lock → викликає get_random_anime() → при успіху
викликає publish_anime() → повертає словник зі статусом результату.

Функція: publish_anime()
Де: services/publisher.py
Призначення: Публікація одного аніме від початку до кінця.
Як працює: Відкриває сесію БД → форматує текст → надсилає в Telegram →
додає запис PublishedAnime → робить commit в одній транзакції. При помилці —
rollback.

Функція: get_random_anime()
Де: scripts/get_random_anime.py
Призначення: Вибір найкращого кандидата для публікації.
Як працює: Два SQL-запити (топ-300 за популярністю + 200 рандомних) →
Python-фільтрація (cooldown, опис) → розрахунок ефективної ваги (базова ×
штраф) → сортування → random.choice з топ-50.

Функція: calculate_weight()
Де: scripts/get_random_anime.py
Призначення: Числова оцінка пріоритету аніме.
Як працює: Комбінує рейтинг, log10(members), бонус за рік виходу, бонус за
кількість серій та статус. Повертає значення > 0 завжди.

Функція: can_publish()
Де: scripts/get_random_anime.py
Призначення: Перевірка cooldown — чи дозволена повторна публікація.
Як працює: Порівнює дату останньої публікації з поточним часом та cooldown
для статусу аніме. Для ongoing з новими епізодами — скорочений мінімальний
cooldown (2 дні).

Функція: get_penalty_multipliers()
Де: app/priority_weights.py
Призначення: Розрахунок штрафних коефіцієнтів для категорій.
Як працює: Аналізує частоту кожної категорії в останніх N публікаціях,
розраховує відхилення від рівномірного розподілу, повертає множники від
MIN_PENALTY до 1.0.

Функція: send_post_with_cache_async()
Де: bot/telegram_sender.py
Призначення: Ефективна відправка фото з кешуванням.
Як працює: Якщо є tg_file_id — надсилає через нього. При BadRequest — очищує
кеш і завантажує заново. Якщо немає file_id — завантажує через httpx, надсилає
байти, зберігає отриманий file_id у БД (в тій самій сесії, що й publisher).

Функція: enrich() [scripts/enrich_anime.py]
Призначення: Курсорна обробка аніме з NULL-полями.
Як працює: Курсорна пагінація (WHERE id > last_id) замість OFFSET для
стабільності на великих таблицях. Retry при HTTP 429/timeout. Checkpoint
після кожного батчу.

6. СТРУКТУРА БАЗИ ДАНИХ
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Таблиця: anime
Призначення: Головний каталог аніме.
Поля:
  id              — внутрішній первинний ключ
  shikimori_id    — зовнішній ідентифікатор на Shikimori
  title_ru        — назва (основна, для поста)
  title_en        — назва англійською
  title_original  — оригінальна назва (японська)
  description     — опис
  status          — released / ongoing / anons
  kind            — tv / movie / ova / ona / music / cm / pv
  episodes        — загальна кількість серій
  episodes_aired  — вийшло серій (для ongoing)
  year            — рік виходу
  rating          — оцінка (0.0 – 10.0)
  members         — кількість користувачів, що відстежують
  image_url       — URL постера
  tg_file_id      — Telegram file_id для кешування (NULL до першої відправки)
Зв'язки: many-to-many з Genre через таблицю anime_genre

Таблиця: genre
Призначення: Довідник жанрів.
Поля:
  id   — первинний ключ
  name — назва жанру (англійська, як на Shikimori)
Зв'язки: many-to-many з Anime

Таблиця: anime_genre (асоціативна)
Призначення: Зв'язок між аніме та жанрами.
Поля: anime_id, genre_id

Таблиця: published_anime
Призначення: Журнал публікацій — основа для cooldown-логіки.
Поля:
  id          — первинний ключ
  anime_id    — посилання на Anime
  status      — статус аніме на момент публікації
  episodes    — кількість серій на момент публікації
  published_at — UTC-час публікації
Зв'язки: many-to-one з Anime
Примітка: episodes зберігається для визначення, чи вийшли нові серії
у ongoing-аніме відтоді.

7. ПОТІК ВИКОНАННЯ (FLOW)
━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

Сценарій: автоматична або ручна публікація аніме

1. ІНІЦІАЦІЯ
   Автопостинг: auto_poster_loop() прокидається після sleep(interval)
   Ручний: адмін надсилає /post_now

2. ПЕРЕВІРКА БЛОКУВАННЯ (post_cycle.py)
   Захоплення file lock → якщо lock зайнятий → статус "locked", вихід
   Встановлення is_posting_now = True у RuntimeState

3. ВИБІР АНІМЕ (get_random_anime.py)
   → SQL: топ-300 за members + 200 рандомних (фільтри якості в запиті)
   → Python: фільтр по cooldown (can_publish) та мінімальній довжині опису
   → Розрахунок ваги: calculate_weight × get_penalty_for_anime
   → Сортування, random.choice з топ-50

4. ФОРМУВАННЯ ПОСТА (formatter.py)
   → Очищення BBCode з опису
   → Обрізання до MAX_DESCRIPTION_LENGTH
   → Підстановка хештегів жанрів
   → Складання фінального шаблону

5. ВІДПРАВКА В TELEGRAM (telegram_sender.py)
   → Є tg_file_id? → надсилання через file_id
   → Немає / BadRequest → завантаження через httpx → надсилання байтів
   → Отримання нового file_id від Telegram → запис у сесію БД (без commit)

6. ЗАПИС У БАЗУ ДАНИХ (publisher.py)
   → Додавання PublishedAnime до сесії
   → session.commit() — один коміт для file_id + PublishedAnime
   → При помилці: session.rollback(), re-raise

7. ЗАВЕРШЕННЯ
   is_posting_now = False
   Звільнення file lock
   Повернення статусу до auto_poster або Telegram

  Коли: одноразово при первинному наповненні БД або після очищення.
